変更差分を分析し、適切な日本語コミットメッセージを生成してGitコミットを作成してください。

## 手順

1. `git status` と `git diff --staged` および `git diff` を実行して、現在の変更内容を把握する
2. ステージされていない変更がある場合、関連するファイルをステージングする（機密ファイルは除外）
3. `git log --oneline -10` で直近のコミット履歴を確認する
4. 変更内容を分析し、以下のルールに従ってコミットメッセージを生成する
5. ユーザーにコミットメッセージを提示し、確認を取る
6. 確認後、コミットを実行する

## コミットメッセージのルール

- **形式**: `[#issue番号] type: 日本語の説明`
- 先頭に関連するissue番号を `[#番号]` の形式で付与する
- 関連issueが不明な場合はユーザーに確認する（issueがない場合は省略可）
- typeは英語: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `style`, `perf`, `ci`, `build`
- コロン以降の説明は**日本語**で記述
- 1行目は70文字以内を目安に簡潔に
- 必要に応じて空行の後に本文を追加（本文も日本語）
- 変更の「何を」ではなく「なぜ」を重視する

## コミットメッセージ例

```
[#1000] feat: 習慣の完了状態をトグルする機能を追加
[#1023] fix: カレンダー表示で日付がずれる問題を修正
[#980] refactor: リポジトリ層のエラーハンドリングをResult型に統一
[#1100] docs: READMEにセットアップ手順を追記
[#1050] test: HabitUseCaseのユニットテストを追加
[#1200] chore: 依存パッケージを更新
```

## コミット分割

- 変更が複数レイヤーにまたがる場合は、レイヤーごとにコミットを分割する
- 分割の粒度: `domain/` → `data/` → `presentation/` → `test/` の順でコミットする
- 各コミットのメッセージは同じissue番号・typeを使い、説明でレイヤーを区別する
- 生成コード（`.freezed.dart`, `.g.dart`）は対応する手書きコードと同じコミットに含める
- 1レイヤーのみの変更や軽微な変更は分割せず1コミットでよい

## 注意事項

- `.env`、認証情報、秘密鍵などの機密ファイルはコミットしない
- 変更がない場合は空コミットを作成しない
- コミットメッセージの末尾に `Co-Authored-By` を付与する
