GitHub Issue $ARGUMENTS の内容を読み取り、実装計画を立てて実装してください。

## 手順

### 1. Issueの読み取り
- `gh issue view` コマンドでissueの内容（タイトル、本文、ラベル、コメント）を取得する
- issueの要件を整理・把握する

### 2. ブランチの作成
- Issueの種類と番号からブランチ名を生成する
- 形式: `<type>/#<issue番号>`
  - `feature/#1` — 新機能（feat）
  - `fix/#2` — バグ修正
  - `improve/#3` — 改善・リファクタリング
  - `chore/#4` — メンテナンス
- Issueのタイトルのプレフィックス（`[feat]`, `[fix]` 等）から種類を判断する。判断できない場合はユーザーに確認する
- `git switch -c <ブランチ名>` で新しいブランチを作成して切り替える
- mainブランチ以外にいる場合は、先にmainに切り替えてからブランチを作成する

### 3. コードベースの調査
- CLAUDE.mdのアーキテクチャルールを確認する
- 関連する既存コードを調査し、影響範囲を把握する
- 既存の実装パターンやコーディング規約を確認する

### 4. 実装計画の作成
- 変更が必要なファイルと変更内容をリストアップする
- CLAUDE.mdのレイヤールールに従っていることを確認する:
  - `domain/` は `data/` や `presentation/` に依存しない
  - `data/` は `domain/` で定義されたインターフェースを実装する
  - `presentation/` は `data/` に直接依存しない
- 単純なCRUDにはuse caseを作らない（実際のビジネスロジックがある場合のみ）
- エラーハンドリングは `Result<T>` を使用する
- 計画をユーザーに提示し、承認を得る

### 5. 実装
- 承認された計画に沿って実装する
- immutableなデータクラスには `freezed` を使用する
- 状態管理には `@riverpod` アノテーション + コード生成を使用する
- ナビゲーションには `go_router` を使用する
- 必要に応じて `dart run build_runner build` でコード生成を実行する

### 6. 検証
- `flutter analyze` で静的解析エラーがないことを確認する
- `flutter test` でテストが通ることを確認する
- 必要に応じて新規テストを追加する

### 7. 完了
- 実装結果をユーザーに報告する

## 注意事項

- 引数が指定されていない場合は、issue番号またはURLの入力を求める
- issueが見つからない場合はエラーメッセージを表示する
- 実装の前に必ず計画を提示してユーザーの承認を得る
